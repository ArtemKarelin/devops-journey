Навигация и работа с файлами

Дальше о том как находить файлы и понимать их природу глубже чем просто ls



1.find
	Самая мощная команда поиска файлов - ищет по реальному обходу файловой системы в реальном времени

	find /home/user -name "*.txt"          # найти все .txt файлы в указанной папке (и вложенных)
	find . -name "config*"                  # искать от текущей папки
	find . -iname "*.TXT"                   # -i — игнорировать регистр
	find . -type f                          # только файлы
	find . -type d                          # только директории
	find . -type l                          # только симлинки
Поиск по свойствам:
	find . -size +100M              # файлы больше 100 МБ
	find . -mtime -7                # изменённые за последние 7 дней
	find . -mtime +30               # изменённые больше 30 дней назад
	find /var/log -name "*.log" -mtime +30   # старые логи — классика для очистки места
Самое ценное — find умеет сразу выполнять действие над найденным:
	find . -name "*.tmp" -delete                     # удалить все найденные .tmp файлы
	find . -name "*.sh" -exec chmod +x {} \;          # применить chmod к каждому найденному файлу
{} — подстановка найденного файла, \; — обязательное завершение команды. Это база для автоматизации: например,
найти и удалить все временные файлы старше недели одной командой.

2. locate
Тоже поиск файлов по имени, но работает по-другому - не обходит диск заново, а ищет в 
заранее построенном индексе(базе данных).
	locate nginx.conf
Разница с find:

locate — мгновенный, потому что просто читает индекс
find — медленнее, но всегда актуален (реально сканирует диск сейчас)
Индекс locate обновляется по расписанию (обычно раз в сутки через cron), поэтому только что созданный файл locate может не найти, пока не обновишь базу вручную: sudo updatedb

На практике: locate — для быстрого "где вообще лежит этот файл", find — когда нужна точность и свежие данные или сложные условия (по размеру, дате, с действием exec).

Кстати, locate не всегда стоит из коробки — иногда нужно доустановить (mlocate пакет).

3. tree

Показывает структуру папки в виде дерева - визуально, а не построчным списком как ls

	tree
	tree -L 2          # ограничить глубину — только 2 уровня вложенности
	tree -a             # показать скрытые файлы тоже
	tree -d             # только директории, без файлов
Не стоит в системе по умолчанию почти нигде — ставится отдельно (apt install tree).
Удобен, когда нужно быстро понять структуру проекта/сервера, особенно перед тем как разбираться в незнакомом codebase или конфигах.

4. ln (link)

Создаёт ссылки на файлы. В Linux их два принципиально разных вида — это важно понять правильно.
Символическая ссылка (symlink) — как ярлык в Windows, отдельный файл-указатель на путь к оригиналу:
	
	ln -s /path/to/original.txt shortcut.txt

Если удалить оригинал — symlink остаётся, но становится "битым" (указывает в никуда). 
Symlink может указывать на файл на другом диске/разделе. В ls -l symlink виден отдельным типом


Жёсткая ссылка (hard link) — это не указатель, а ещё одно имя для того же самого содержимого на диске:

	ln original.txt hardlink.txt

Оригинал и hard link — полностью равноправны, оба указывают на одни и те же данные (один и тот же inode).
Удалишь один — данные останутся живы, пока существует хотя бы одна ссылка. Ограничение:
hard link не может указывать на директорию и не может пересекать границы файловой системы (разные диски/разделы).
	
5. stat 

Показывает подробную техническую информацию о файле — куда больше, чем ls -l.

	stat file.txt

6. file

Определяет реальный тип файла — не по расширению (которое можно как угодно подделать/переименовать), а по его фактическому содержимому (сигнатуре, magic bytes).

	file document.pdf         # выведет: PDF document, version 1.7
	file script.sh             # Bourne-Again shell script
	file image.jpg              # JPEG image data, ...
	file mystery_file            # если кто-то переименовал .exe в .txt — file всё равно скажет правду

Полезно, когда получаешь файл без расширения или сомнительный файл с сервера и нужно быстро понять, что это вообще такое, не открывая его вслепую.
