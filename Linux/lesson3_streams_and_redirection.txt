Потоки и перенаправления

Это одна из самых важных тем в Linux вообще — без неё нельзя по-настоящему понять, как работают команды, скрипты и логирование.

Существует три стандартных потока

Когда запускается любая программа в Linux, у неё автоматически открыты три канала для обмена данными с окружением. Каждый имеет числовой идентификатор — file descriptor (fd):

Поток	Название	Номер (fd)	Что это
stdin	standard input	0		откуда программа читает входные данные (обычно клавиатура)
stdout	standard output	1		куда программа выводит обычный результат (обычно экран)
stderr	standard error	2		куда программа выводит ошибки (тоже обычно экран, но это отдельный канал)


Ключевая идея: stdout и stderr — это два разных потока, даже если оба по умолчанию выводятся на экран и визуально неотличимы.
Это разделение существует специально — чтобы можно было обрабатывать нормальный вывод и ошибки отдельно друг от друга.

Проверим это:

	ls existing_file.txt nonexistent_file.txt

existing_file.txt уйдёт в stdout, а сообщение об ошибке No such file or directory — в stderr. На экране ты видишь оба вперемешку, но программно это два разных канала.

1. Перенаправление вывода: > и >>

> — перенаправить stdout в файл, полностью перезаписав его содержимое:

	echo "hello" > file.txt        # file.txt теперь содержит только "hello"
	ls -la > listing.txt             # результат ls записался в файл вместо экрана

Осторожно: > стирает файл без предупреждения, даже если файл был большим.

	>> — добавить (append) в конец файла, не удаляя существующее содержимое:
	
	echo "новая строка" >> log.txt

Именно так пишутся логи скриптов — каждый запуск дописывает новые строки, не уничтожая историю.

2. Перенаправление ошибок: 2>

	Поскольку stderr — это поток номер 2, перенаправляется он через 2>:

	find / -name "*.conf" 2> errors.log

Это выполнит поиск по всей системе, а все сообщения об ошибках (типа "Permission denied" при попытке зайти в защищённые папки) улетят в errors.log, 
а не засорят экран — на экране останутся только реальные найденные файлы (stdout).

3. Объединение потоков: 2>&1

Иногда нужно, чтобы и обычный вывод, и ошибки шли в один файл:
	
	command > output.log 2>&1

Разберём этот синтаксис по частям, потому что он реально путает новичков:

	> output.log — сначала stdout направляется в файл
	2>&1 — читается как "направь поток fd 2 (stderr) туда же, куда сейчас смотрит fd 1 (stdout)"
	&1 — амперсанд означает "это не имя файла с названием 1, а ссылка на файл-дескриптор номер 1"

Порядок критичен. Если написать наоборот:

	command 2>&1 > output.log

Это не сработает как ожидается: сначала stderr скопируется туда, куда stdout смотрел на тот момент (то есть на экран), и только потом stdout перенаправится в файл.
В итоге ошибки останутся на экране, а не в файле. Правило: 2>&1 пишется после >.

Более современный короткий вариант, который делает то же самое:

	command &> output.log       # и stdout, и stderr сразу в файл

Отдельный частый паттерн — выбросить вывод вообще, никуда не сохраняя:

	command > /dev/null 2>&1

/dev/null — специальный "чёрный ящик" в Linux: всё, что туда пишешь, исчезает безвозвратно.
Используется, когда результат команды не нужен вообще, но нужно, чтобы она отработала молча (частый паттерн в cron-задачах).

4. Перенаправление ввода: <

Менее используемый, но важный:
	
	sort < unsorted.txt

Вместо того чтобы sort ждал ввода с клавиатуры (stdin), он читает данные из файла.

5. Пайпы |

Пайп — это связь между командами: stdout одной команды становится stdin следующей, напрямую, без промежуточного файла.

	ps aux | grep nginx

Здесь ps aux выводит список всех процессов → этот вывод не идёт на экран, а сразу передаётся как вход в grep nginx, который отфильтровывает только строки со словом "nginx".

Пайпы можно (и нужно) цеплять цепочкой — это и называется "однострочники" (one-liners)

	cat access.log | grep "404" | wc -l

Читаем слева направо как конвейер:

	cat access.log — вывести содержимое лога
	| grep "404" — оставить только строки с кодом 404
	| wc -l — посчитать, сколько таких строк

Важное различие: | vs >
> соединяет команду с файлом
| соединяет команду с другой командой
